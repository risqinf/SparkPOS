PRD — Sistem POS Offline Native Windows (.NET Stack)

Versi: 1.0 · Status: Draft untuk Development · Tujuan Dokumen: Spesifikasi teknis lengkap sebagai input untuk tim developer maupun AI coding agent (Antigravity/agentic IDE) agar implementasi konsisten tanpa ambiguitas.

1. Ringkasan Eksekutif

Aplikasi kasir (POS) offline-first, native Windows, dibangun dengan .NET untuk efisiensi RAM dan kecepatan. Didistribusikan dengan model sewa/lisensi (subscription), sehingga aplikasi wajib memiliki sistem proteksi lisensi yang solid meski berjalan offline. Target pasar: UMKM retail & F&B di Indonesia dengan spek PC kasir rendah-menengah.

2. Tujuan Produk

  • Software kasir ringan (idle RAM < 100 MB) yang tetap penuh fitur setara software POS komersial.
  • Berjalan 100% offline untuk operasional harian; koneksi internet hanya dibutuhkan untuk validasi lisensi & sinkronisasi opsional.
  • Mendukung model bisnis rental: aktivasi, perpanjangan, dan penguncian otomatis saat masa sewa habis.

4. Ruang Lingkup

Fase 1 (MVP): Auth & shift, produk & stok, transaksi penjualan, cetak struk, laporan dasar, lisensi & proteksi, backup/restore.

Fase 2: Purchasing/supplier, CRM member & poin, promo lanjutan, multi-outlet sync, export laporan Excel/PDF, customer display.

Di luar cakupan (v1): Akuntansi penuh (jurnal umum), integrasi marketplace, e-commerce, mobile app.

5. Tech Stack Final

Layer Pilihan Alasan
UI Framework WinForms (.NET 8/9) Lebih hemat RAM dari WPF; native Win32, cocok PC kasir low-end
Runtime Native AOT (PublishAot=true) Startup cepat, tanpa JIT overhead, RAM lebih kecil dari mode JIT biasa
Database lokal SQLite + SQLCipher Ringan, file-based, cocok offline; SQLCipher untuk enkripsi data transaksi
Data access Dapper (micro-ORM) Overhead jauh lebih kecil dari EF Core, cocok untuk aplikasi RAM-sensitive
Migrasi skema DbUp atau script SQL manual bervers EF Core Migrations dihindari agar tidak perlu bawa EF Core runtime
Printer thermal ESCPOS_NET ESC/POS raw command, ringan, tidak perlu driver tambahan
Barcode scan/generate ZXing.Net Support generate & baca barcode/QR
Reporting cetak FastReport.NET (opsional) atau layout custom Untuk laporan kompleks; struk pakai ESC/POS langsung
Logging Serilog (file sink, rolling) Untuk audit trail & debugging di lapangan
DI Container Microsoft.Extensions.DependencyInjection Standar, ringan
License server (cloud) ASP.NET Core Minimal API Untuk aktivasi & validasi berkala
Installer Inno Setup Ringan, standar industri Windows
Auto-update Velopack Update binary tanpa reinstall manual

6. Arsitektur Sistem

Pola: Layered Architecture (Presentation → Application → Domain → Infrastructure), single project boleh dipecah per-folder untuk MVP, dipisah per-project di Fase 2.

graph TD
    A[Presentation - WinForms UI] --> B[Application - Services/UseCases]
    B --> C[Domain - Entities & Business Rules]
    B --> D[Infrastructure - SQLite/Dapper]
    B --> E[Infrastructure - Hardware ESC/POS, Scanner]
    B --> F[Infrastructure - License Module]
    F --> G[(License Server API - Cloud)]
    D --> H[(SQLite Encrypted DB - Lokal)]

Prinsip wajib untuk AI agent:

  • Business logic (hitung total, pajak, diskon, stok) TIDAK BOLEH ditulis di code-behind form — wajib di layer Application/Domain agar testable.
  • Semua akses database lewat Repository pattern, tidak ada raw SQL di form.

8. Daftar Fitur Lengkap (Standar POS)

8.1 Autentikasi & Manajemen User

  • Login PIN/password per kasir, multi-role (Admin/Manager/Kasir)
  • Buka/tutup shift dengan input kas awal & rekonsiliasi kas akhir
  • Log aktivitas user (audit trail)

8.2 Produk & Inventori

  • CRUD produk, kategori, satuan (dengan konversi, mis. dus→pcs)
  • Varian produk (ukuran/warna), generate & scan barcode
  • Stok minimum + notifikasi stok menipis
  • Kartu stok (histori mutasi per produk), stock opname
  • Multi-gudang (Fase 2)

8.3 Transaksi Penjualan (Kasir)

  • Pencarian produk cepat (barcode/nama/kode)
  • Hold/park transaksi (transaksi tertunda)
  • Diskon per item & per nota (persen/nominal)
  • Split payment (cash + non-cash dalam satu transaksi)
  • Pembulatan otomatis, kembalian
  • Retur/void dengan approval supervisor (PIN)
  • Cetak & cetak ulang struk, buka cash drawer otomatis

8.4 Pembelian & Supplier (Fase 2)

  • Data supplier, Purchase Order, penerimaan barang → update stok otomatis
  • Retur pembelian

8.5 Pelanggan / CRM Ringan

  • Data member, histori transaksi, poin reward
  • Harga khusus member (Fase 2)

8.6 Promosi

  • Diskon persentase/nominal per periode, promo bundling (Fase 2)

8.7 Laporan

  • Penjualan harian/per-periode/per-kasir/per-produk
  • Laba rugi sederhana (margin kotor)
  • Produk terlaris, laporan stok, laporan kas per shift
  • Export Excel/PDF (Fase 2)

8.8 Hardware Integration

  • Printer thermal 58mm/80mm (ESC/POS)
  • Cash drawer (trigger via printer)
  • Barcode scanner (USB HID/keyboard wedge — plug and play, tanpa driver khusus)
  • Customer display & timbangan digital (opsional, Fase 2)

8.9 Lisensi & Proteksi (Kritis untuk Model Rental)

  • Aktivasi via hardware fingerprint (CPU ID + motherboard serial + MAC)
  • File lisensi lokal terenkripsi (AES-256), signature RSA agar tidak bisa diedit manual
  • Cek masa berlaku lokal setiap start (independen dari koneksi internet)
  • Grace period 7–14 hari saat offline sebelum lock
  • Phone-home berkala ke license server saat online untuk validasi status pembayaran
  • Anti-tamper: validasi expiry dibandingkan timestamp transaksi terakhir di DB, bukan hanya system clock (mencegah mundur jam)
  • Mode "locked/read-only" saat expired — data tetap bisa dilihat, transaksi baru diblok

8.10 Backup & Restore

  • Backup manual & terjadwal (lokal/cloud), restore dari file backup

8.11 Pengaturan

  • Info toko, konfigurasi pajak, kustomisasi header/footer struk, setup printer

9. Kebutuhan Non-Fungsional

Aspek Target
RAM idle < 100 MB (Native AOT + WinForms)
Waktu startup < 2 detik
Operasi Offline-first, tanpa internet wajib untuk transaksi harian
Keamanan data Enkripsi DB (SQLCipher) + enkripsi file lisensi
Kompatibilitas Windows 10/11 64-bit, .NET 8/9 runtime ter-bundle (self-contained)
Kapasitas Minimal 100.000 transaksi tanpa degradasi performa signifikan

10. Panduan Implementasi untuk AI Coding Agent (Antigravity)

  • Struktur folder disarankan: /src/POS.UI (WinForms), /src/POS.Application, /src/POS.Domain, /src/POS.Infrastructure, /src/POS.License, /tests/POS.Tests.
  • Konvensi: business rule (pajak, diskon, validasi stok) wajib punya unit test di POS.Tests.
  • Tidak boleh hardcode connection string, key enkripsi, atau logic lisensi di file yang mudah dibaca plain text.
  • Setiap fitur pada §8 dianggap "Done" jika: (1) ada test untuk logic inti, (2) UI berfungsi end-to-end dengan DB lokal, (3) tidak menambah leak memory saat idle > 30 menit.
  • Bangun modul lisensi (§8.9) paling awal, karena semua modul lain bergantung pada status aktivasi.
